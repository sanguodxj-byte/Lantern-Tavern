# 法术实现审计与交付概览

## 1. 交付范围

本轮完成四项工作：

1. 审计固定法术配方、法术界面、运行时投射物与命中特效的连接状态。
2. 将法术界面接入真实符文库存，并把法术装配纳入 `GameState` 存档。
3. 验证并补齐现有法术投射物命中到 `RuneHitBurst` 粒子爆发的链路。
4. 整理当前法术表与后续明确缺口。

## 2. 当前数据流

```text
GameState.expedition_inventory.runes
  -> GameState.spell_loadout.set_rune_inventory()
  -> CombatHUD._setup_spell_interface()
  -> SpellInterface.configure(loadout, rune_ids)
  -> SpellLoadout.set_rune()
  -> SpellRecipeData.resolve()

SaveManager
  -> GameState.serialize()
  -> spell_loadout.slot_runes
  -> GameState.deserialize()
  -> 先恢复符文库存，再恢复法术装配

ProjectileService
  -> ProjectileEntity
  -> _destroy_with_impact()
  -> RuneEffectHooks.spawn_hit_burst()
  -> RuneHitBurst(GPUParticles3D + OmniLight3D)
  -> finished -> queue_free
```

## 4. 符文库存与存档

- 法术界面不再注入 8 个演示符文；符文列表来自 `GameState.carried_runes`。
- `SpellLoadout` 保存库存数量快照并计算剩余可装配数量。
- 装配本身不消耗库存，但同一枚实体符文不能同时占据多个符文槽位。
- 库存减少时会按槽位顺序清理超量装配，保证装配状态不超过实际拥有数量。
- `GameState.serialize()` 新增 `spell_loadout`；读取时先恢复 `expedition_inventory.runes`，再恢复槽位，兼容旧存档无该字段的情况。
- `SaveManager` 无需单独增加顶层子系统：它原本已持久化 `GameState`，因此法术装配随 `game_state` 一并保存。

## 5. 粒子全链路验证

已确认并补齐：

- 飞行视觉：法术投射物使用发光球体 + `OmniLight3D`。
- 命中配置：`ProjectileData.impact_burst_type` 明确声明爆发类型。
- 默认映射：
  - `elemental_bolt -> FIRE_EXPLOSION`
  - `arcane_bolt -> DARK_DRAIN`
  - `frost_nova_bolt -> STORM`
  - `thunder_bolt -> LIGHTNING_CHAIN`
- 命中/环境碰撞销毁：`ProjectileEntity._destroy_with_impact()` 调用 `RuneEffectHooks.spawn_hit_burst()`。
- 实例化：爆发挂在场景树根节点，避免目标死亡时连带释放。
- 播放：`RuneHitBurst._ready()` 开启 `GPUParticles3D.emitting`。
- 回收：`GPUParticles3D.finished` 连接 `queue_free`，点光源按粒子寿命淡出。

现有限制：这一链路已从“投射物命中”闭合到粒子回收，但固定配方法术仍缺少“选择后实际施放”的输入/状态机入口，所以还不是从法术界面到命中的完整玩家操作闭环。
