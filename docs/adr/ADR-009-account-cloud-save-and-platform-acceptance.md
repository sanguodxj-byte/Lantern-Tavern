# ADR-009: 账号体系 / 云存档 / 平台验收范围（产品层决策）

- 状态：**Accepted（用户拍板：2026-08-03——维持现状，不做账号/云存档）**
- 关联：ADR-001（服务器存档仓）、架构审查 P1-1、验收清单「平台与性能」

## 用户决策（2026-08-03）

**维持现状：本机 `player_guid`（ClientIdentity）+ 服务器存档仓（ServerSaveRepository）。**
不做账号登录、不做云存档后端；联机可玩性以本机服务器仓闭环（服务器重启/重连可恢复）。房间/匹配维持 `docs/24 §1` 排除（第一版不做匹配/NAT 穿透/MMO 持久世界）。

## 维持现状的具体含义

1. **身份**：本地持久化 `user://lantern_identity.cfg` 的随机 GUID（ClientIdentity），服务器按 guid 键控权威状态。
2. **存档**：`user://server_saves/<guid>.json`（进程级）；房主本地存档作为首次播种来源，之后以服务器仓为真相。
3. **平台验收**：Windows/Android 导出预设已就绪（CI 识别门禁）；实际导出与 Android 真机 GPU/热稳定性验收由发布排期执行（需带模板构建机 + 真机）。

## 技术约束（产品后续若改变范围，不得违反）

- 服务器绝不信任客户端自报的权威状态（存档/属性/位置/伤害）；
- 所有权威状态按 `player_guid` 键控，重连/结算幂等由 SaveAuthority + 服务器仓保证；
- 若未来引入账号体系，身份解析在 `ConnectionAuthority` / `ServerSaveRepository` 键控层替换，不侵入战斗/移动/装备策略层；
- 存档迁移按 ADR-005 的 SaveSection 协议执行，避免破坏现有存档格式。

## 后果

- 联机可玩性闭环成立（本机服务器仓），无后端依赖。
- 账号/云存档需求出现时，作为独立产品迭代按上述约束实施。
