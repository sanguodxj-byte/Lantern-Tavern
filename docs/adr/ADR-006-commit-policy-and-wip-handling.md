# ADR-006: 工作树提交策略与预存 WIP 处理

- 状态：**Accepted（立即生效）**
- 关联：架构审查 P2-6、基线 P2-6、第二轮/第三轮报告 §2

## 背景

工作树长期混合数百个脏路径（GLB、纹理、shader、网络、战斗、法术、UI、文档、测试），架构修复与资产生产同快照，误提交与回归定位成本高；`git add -A` 曾导致无法定位回归。

## 决策

1. **按主题拆分提交**（禁止 `git add -A`）：
   - 每提交只含一个领域主题（如 `feat(multiplayer): input tick buffer`、`fix(spell): ray double damage`）；
   - 提交前 `git status`/`git diff` 检查暂存范围；
   - 大文件（GLB/纹理）与源码分开提交。
2. **预存 WIP 归属**：工作树中未提交的敌人重构 / 地牢优化 / 模型资产再生成 / 酿酒系统属于各自功能迭代，**由对应功能提交收尾**，不混入架构整改提交；架构整改相关文件按本策略逐主题提交。
3. **审查证据入库**：架构审查/整改结论进入受跟踪的 `outputs/`（已在仓库内）与 `docs/adr/`（本轮建立）；临时截图/日志继续留在 ignored `reports/`。
4. **基线纪律**：合并任何主题前，相关测试套件必须通过（审查相关套件 0 orphan + 退出 0）。

## 后果

- 回归可定位到单一主题提交；`git bisect` 可用。
- 发布候选在干净主题分支上复跑全量 gdUnit4（基线验收清单「工程」项）。
