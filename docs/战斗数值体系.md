## 2. 伤害结算主流程

全部来源：`globals/combat/damage_resolver.gd`（已硬编码）。

### 2.1 基础伤害
- 骰子均值（无 RNG）：`dice_avg = count × (sides+1) / 2.0` `:260`
- 原始伤害：`raw = (dice_avg + weapon_flat + stat_flat) × weapon_damage_mult`，再叠 `base_damage_bonus_percent` `:257-274`
- 风格平砍加成见 §1.3

### 2.2 暴击（唯一概率环节）【✅ 文档·已决定·修复 §9 #2/#4】

- 暴击率（近战/远程，PER 驱动）：
  `crit_rate = 5.0 + atk.per×0.5 − def.per×0.5 + crit_bonus`，下限 **0** `:198-199`
- 暴击率（法系，MAG 驱动 — 修复 §9 #4）：
  `spell_crit_rate = 5.0 + atk.mag×0.5 − def.per×0.5 + crit_bonus`
  > 原代码法系暴击误用 PER（`damage_resolver.gd:198`），已改为由 MAG 驱动，与法术伤害轴一致。
- **暴击倍率（已修复缩放 — 修复 §9 #2）**：
  `crit_mult = 1.5 + crit_dmg_bonus + min(atk.per×0.02, 1.0)`
  - `PER×0.02`：每 **50 PER +1.0（100%）** 暴伤；封顶 `1.0` → 暴伤倍率上限 **2.5×**（PER≥50 封顶）。
  - 移除原 `− def.per×0.01`（暴伤是攻方输出能力，守方 PER 不应削弱）。
  - 法系暴伤：`spell_crit_mult = 1.5 + crit_dmg_bonus + min(atk.mag×0.02, 1.0)`。
  - 下限 **1.1** `:206-207`（代码占位，待对齐）。
- 掷骰：`randi_range(1,100) <= int(crit_rate)` 或 `force_crit` `:200-201`

### 2.3 防御结算【✅ 文档·已决定·修复 §9 #1 平减缺陷】

> **已废弃旧模型**：`final = max(1, base − (armor_def+con))` 平减法（大伤归零、小伤被 `max(1)` 吞掉、两头失效）。改为**伤害相关百分比减伤**（PoE2 / Brotato 家族），详见 §9.1 #1。

- **减伤基值 `def`**：`def = (armor_def + con) × (1 − ignore_def_percent/100)` `:226,229-230`
  - 骷髅 + 锤被动：`def = 0`（无视防御）` :228`
- **百分比减伤（核心）**：
  `mitigation% = def / (def + k × base)`，`k = 8`（**可调 6~12**）
  - `base` = 进入防御前的伤害（已含 流派/材质/暴击/朝向 修正）。
  - 减伤随**伤害大小自适应**：小伤/多段被显著吸收，巨伤（boss/区域 `dmg_mult`）按比例穿透——防御不再后期摆设。
  - **硬封顶 90%**：`mitigation% = min(mitigation%, 0.90)`，避免叠甲无敌。
- **里程碑绝对减免（在百分比之后叠加）**：`flat_reduce = Σ 里程碑平减`（厚实皮肤 −2、元素护壳 −4 等）`milestone_effects.gd`。
- **收口**：
  `post_mit = base × (1 − mitigation%)`
  `final_damage = max(1, round(post_mit − flat_reduce))`

**参考表（k=8，def = armor_def + con）**

| 场景 | def | base | 减伤% | 实收 |
|---|---|---|---|---|
| 轻甲 vs 小伤 | 20 | 20 | 33.3% | 13 |
| 中甲 vs 普攻 | 40 | 50 | 9.1% | 45 |
| 重甲 vs 普攻 | 80 | 50 | 16.0% | 42 |
| 重甲 vs 小伤 | 80 | 20 | 33.3% | 13 |
| 任意甲 vs Boss 巨伤 | 60 | 200 | 3.2% | 193 |
| 高甲 vs 普攻（堆到顶） | 120 | 50 | 23.1% | 38 |

> 结论：防御对**小/中伤害**有效、对**巨伤**按比例穿透，符合预期；`max(1)` 下限保留，绝不归零。代码 `damage_resolver.gd:226-235` 仍为平减占位，**待对齐（本次未动）**。

### 2.5.0 流派定位与区分矩阵【✅ 已决定·设计总纲】

> **设计红线**：七流派**不在 DPS 层面拉平**（见 §2.5.5），而是靠**输出方式 + 加成侧重 + 机制复杂度 + 生存手段**四轴错开，做出玩法辨识度。每个流派必须有一句能立住的定位，且与其余六个**不重叠**。

| 流派 | 一句话定位 | 输出来源 | 加成侧重 | 机制复杂度 | 生存 / 特色手段 | 核心专精（doc21） |
|---|---|---|---|---|---|---|
| **双手** `TWO_HAND` | **纯平A流·硬核直球** | **基础平砍**（单发最高） | **绝大部分加成绑定平A** | **最低（无花样机制）** | 蓄力抗打断 + 减伤 | 蓄势 / 重型挥舞 |
| **单手** `ONE_HAND` | 平衡全能·单体爆发 | 平砍 + 锁定爆发 / 剑接法术 | 单体锁定增益、暴击 | 中 | 高闪避、灵活走位 | 决斗者 / 奥法之剑 |
| **双持** `DUAL_WIELD` | 高频连携·节奏连击 | **左右手交替连携**（多段） | 连携触发（暴击 / 破防） | 高（连携时机） | 十字架招架反击 | 交错挥砍 / 十字返 |
| **持盾** `ONE_HAND_SHIELD` | 坦克反制·最低输出 | 盾击压制（输出最低） | 减伤、压制、反射 | 中（防御时机） | 格挡减伤 + 远程反射 | 盾击 / 折射 |
| **徒手** `UNARMED` | 极限攻速·抓取处决·投射物反制 | 高频平砍 + 处决 + 抓取投摔 + 踢击普攻化 + 折箭 | **攻速叠加**、真实伤害处决、擒拿、迅猛踢击、折箭 | 中高（叠层 / 长按 / 双键） | 最高机动、过肩摔 / 擒拿投掷、迅猛踢击、折箭术 | 暴风骤雨 / 过肩摔 / 擒拿 / 迅猛踢击 / 折箭术 |
| **远程** `RANGED` | 距离精准·穿透风筝 | 弹道（爆头 / 贯穿） | 弱点暴击、穿透 | 中（瞄准 / 蓄力） | 拉开距离、风筝 | 看破弱点 / 贯穿 |
| **法系** `SPELL` | 法术主输出·武器形同虚设 | **法术卡**（武器平A极弱 0.50） | 法术、元素状态、护盾 | 高（法术组合） | 蓝转护盾、元素环 | 奥术护盾 / 元素环 |

> **双手 = 平A流锚点（用户拍板）**：双手**没有花样机制**，就是"抡起来平砍最疼"。它的两项专精都服务于**强化基础攻击本身**——`重型挥舞` 直接替换平砍动作为大范围横扫（扩扇形 / 碰撞半径），`蓄势` 强化蓄力平砍（抗打断 + 减伤 + 承伤转追加伤害）。因此**双手的加成应尽量挂在平砍上**（伤害倍率 1.35 全流派最高、单发最高），而不是引入独立连招 / 触发式机制。这与双持（靠连携多段）、徒手（靠攻速叠层）形成明确对比：**同为近战，双手走"少而重的平A"，双持走"多而快的连携"，徒手走"极快叠攻速 + 处决"**。

> **区分自检（避免重叠）**：
> - 双手 vs 单手：双手纯平A、上限高、操作最简单；单手靠**锁定单体**打爆发、可**接法术**，更灵活。
> - 双手 vs 双持：都是近战 DPS，但双手=**单发大平砍 + 慢**，双持=**多段快连携**（平A本身不强，靠连携倍增）。
> - 持盾 vs 双手：持盾输出**最低**，价值在减伤 / 压制 / 反射，与双手的纯输出定位相反。
> - 法系 vs 其余：法系**武器平砍形同虚设**（0.50），真正输出在法术卡，独立成体系。

### 2.5 流派武器伤害倍率 `damage_mult`【文档·已决定（部分）】

> **定义**：`damage_mult` 乘在 **武器平砍 / 武器技能伤害** 上，**仅作用于武器伤害**。

### 2.5.2 流派武器冷却倍率 `attack_speed_mult`【✅ 已决定】

> **语义（设计规则）**：`attack_speed_mult` 决定**武器冷却时长**——不是「攻速加成」这种软概念，而是**硬锁**：冷却期间**禁止发起攻击，必须等待冷却结束**。
> `武器冷却 = BASE_ATTACK_INTERVAL(1.0s) ÷ (attack_speed_mult × 灵巧加成)`，其中 `灵巧加成 = 1.0 + DEX×0.005`（每点灵巧 +0.5% 攻速，`combat_engine.gd:33,54-57`）。
> 与敌人 `enemy_state_moving.gd:132-133` 的 `can_attack()` 时间锁（`time_since_last_attack > duration_between_attacks`）**同构**——玩家也应如此实现。
>
> ⚠️ **代码缺口（玩家侧）**：当前 `compute_attack_interval` 仅被**敌人实际执行**（enemy 有 `time_since_last_attack` + `duration_between_attacks` + `can_attack()` 时间锁）；`scenes/characters` 下**只有敌人**有 `time_since_last_attack`，**玩家侧未找到等价的冷却锁**——即「玩家武器冷却」概念尚未落地，须实现对齐本文档（见 §9 #9）。

### 2.9 闪避判定（命中后·补回）【✅ 文档·已决定】

> **设计定位**：与「命中恒 true、无攻击投骰」规则**不冲突**——闪避发生在**命中确认之后**：hitbox 已接触（命中=true），守方再掷一次判定是否"卸力闪开"。表现即**命中后显示 MISS、不造成伤害**。

- **闪避率来源（守方）**：`dodge_rate = AGI×1.0% + Σ装备/词缀闪避 + 虚实避让(+6%)`；近战额外叠 `侧垫步` 的 10%（AGI T1，仅近战）。
- **硬上限**：`dodge_rate = min(dodge_rate, 0.75)`（防叠甲无敌；可调 0.60~0.80）。
- **判定时机**：在 §3.1 命中确认**之后**、§2.1 基础伤害**之前**插入。
- **掷骰**：`randi_range(1,100) <= int(dodge_rate×100)` → 闪避成功。
- **成功效果**：
  - `final_damage = 0`；
  - 弹出 **MISS** 浮字（`damage_number` miss 样式，独立于伤害数字）；
  - **跳过**后续暴击 / 状态异常 / 击退 / 动量（§2.8）/ 朝向加成结算——视为"未实打中"。
- **失败**：照常进入 §2.1 → §2.3 完整管线。
- **不与以下冲突**：翻滚 i-frame（§4，期间不可被选中，非掷骰）；侧垫步（近战 10% 独立骰，可与基础闪避分别判定或加和封顶）；`ignore_def` / 防御减伤（仅作用于未闪避的实伤）。

> 代码现状：`attr_panel.gd:212-216` 仅算 UI 展示值，`damage_resolver.gd` 无闪避分支——**本次仅文档决定，代码未对齐（按"不对齐代码"指令保留占位）**。

### 9.1 伤害公式缺陷与业界对比（分析）

**业界地牢 / ARPG 防御与伤害模型对照**

| 游戏 | 防御模型 | 核心公式 / 特征 |
|---|---|---|
| **DCSS** | 平减 + GDR 保底 | AC 随机减 `0..AC`；GDR 保底 `min(AC^(1/4)×16% × 伤害, AC/2)`；明确"non-linear，AC 对小伤害更有效" |
| **ToME 4** | 百分比抗性 + 平减(封顶) | `final = base × (100 − eff_res)/100`；`flat_damage_armor` 绝对减伤但 `min(dam, flat)`；**暴击伤害随 `combat_critical_power` 缩放** |
| **PoE / PoE2** | 伤害相关百分比减伤 | `reduction = AR / (AR + 10×DMG)`，硬上限 90%；小伤强、巨伤弱 |
| **Brogue** | 纯闪避（防御=命中惩罚） | `hit% = acc × 0.987^def`；护甲只降被命中率，不减伤 |
| **Brotato 土豆兄弟** | 百分比减伤(递减) | `减伤% = 护甲 / (护甲 + 100)`，边际递减 |

> **共识**：现代地牢 / ARPG 已弃用纯平减。DCSS 自身从纯平减补了 GDR；PoE / ToME / Brotato 一律走"百分比 / 非线性减伤"。原因见下方缺陷 #1。

**当前公式（§2）明显缺陷**

1. **【严重】平减防御 + `max(1)` 下限 = 已废弃的 DCSS 旧模型**
   `final = max(1, base − (armor_def + con))`。问题：① 大伤（boss / 区域 `dmg_mult`）时 `(armor+con)` 可忽略→防御后期归零；② 小伤 / 多段时 `max(1)` 已把所有伤害压到 1→平减毫无意义；③ CON 既给 HP×10 又给 +1 防御"双重获利"，但配合平减仍扛不住大伤。DCSS 正是因此补了 GDR 保底。
   → 建议改 `mitigation% = def / (def + k × base)`（k≈8~12，PoE / Brotato 家族），防御随伤害大小自适应，且天然尊重 `max(1)` 下限。

2. **【明显·疑似 bug】暴击伤害倍率不缩放**
   `crit_mult = 1.5 + atkPER×0.01 − defPER×0.01 + crit_dmg_bonus`。`PER×0.01` = 每 100 点 PER 仅 +1% 暴伤→任何合理 PER(<100) 下 `crit_mult` 恒等于 1.5，投资暴伤无意义（除非被动给 `crit_dmg_bonus`）。ToME 用 `combat_critical_power` 实打实缩放暴伤。
   → 建议 `crit_mult = 1.5 + crit_dmg_bonus + min(PER×0.02, cap)` 或接入专用暴伤属性。

3. **【明显】进攻线性无限 × 防御平减 = 滚雪球**
   `stat_flat = STR×1.5`（及 DEX / MAG）永远线性；`weapon_flat` 加法；无收益递减（§1.6 软上限未落代码）→ 后期进攻暴涨、平减防御被甩开，只剩堆 HP。而 `ignore_def_percent` 反而是百分比（好模型）→ 两种模型混用。
   → 配合 §1.6 软上限 + 改 #1 的百分比减伤，使防御能跟上进攻曲线。

4. **【明显·半接线】法系（法术）路径未闭环**
   `attack_type="spell"` 走 `stat_flat = MAG×1.5`，但：① MAG→法力池未派生（§9 #10），法系无资源；② 暴击用 `5 + 攻方PER×0.5 − …` → 法术暴击竟由 PER 决定而非 MAG；③ 法术卡倍率在统一结算里无落点（文档说"由法术卡自身决定"）。ToME 给法术独立伤害类型 + 抗性管线。
   → 明确法术伤害结算路径、法术暴击源、MAG→法力闭环。

5. **【次要·genre 落差】无伤害类型 / 抗性系统**
   火 / 冰 / 雷 / 毒词缀仅作伤害标签（§9 #4），无独立 DOT / 抗性。业界（PoE / ToME）抗性是关键防御轴；若想让 `ember×1.20` 等元素武器在防御侧也成立，需补抗性管线（非必做，标注为设计取舍）。

> **注**：伤害零方差（确定性 `dice_avg`，§2.1）是**刻意设计**，非缺陷——但零方差 + 平减 + `max(1)` 三叠加，使战斗完全可预测、缺"手感纹理"，敌 HP 必须精确标定否则像脚本。列为取舍提示，不强行改。

**优先级**：#1 防御模型 > #2 暴伤 bug > #4 法系闭环 > #3 滚雪球 > #5 可选。

### 9.1.1 缺陷修复方案【✅ 文档·已决定·代码未对齐】

> 以下修复**仅落地到本文档设计层**，按用户要求**未改动任何代码**。`damage_resolver.gd` / `mana_component.gd` 相关常量仍为占位符，留待后续单独对齐。

**#1 防御模型（§2.3）**
- 废弃平减 `base − (armor+con)`，改伤害相关百分比减伤：`mitigation% = def/(def + 8×base)`，封顶 90%。
- `def = (armor_def+con)×(1−ignore_def%/100)`，骷髅+锤→0；里程碑平减（厚实皮肤−2/元素护壳−4）作为百分比后绝对减免叠加；`final = max(1, round(base×(1−mit%) − flat))`。

**#2 暴伤缩放（§2.2）**
- `crit_mult = 1.5 + crit_dmg_bonus + min(PER×0.02, 1.0)`（上限 2.5×）；移除 `− defPER×0.01`。

**#4 法系闭环（§1.4 + §2.2）**
- MAG→法力：`max_mana = 50 + eff_MAG×10`、`regen = 2.0 + eff_MAG×0.1`。
- 法系暴击由 MAG 驱动：`spell_crit_rate = 5 + MAG×0.5 − defPER×0.5`；`spell_crit_mult = 1.5 + crit_dmg_bonus + min(MAG×0.02, 1.0)`。
