# Lantern Tavern UI 术语定义表

本表是装备界面与物品交互相关术语的当前语义来源。用户在会话中的明确解释优先于旧截图、旧代码命名和代理的推断。

| 术语 | 当前定义 | 适用范围 / 备注 |
| --- | --- | --- |
| 网格 | 右侧物品页中的背包物品网格，用于展示全部、装备、材料和符文等物品。 | **不指左侧防具槽、武器主副手槽，也不指技能槽。** |
| 背包网格 | “网格”的完整称呼，指右侧物品标签页的 `GearList`。 | 整理、分类排列、淡暗金色正方形色块都只作用于此区域，除非用户另行说明。 |
| 装备槽 / 槽位 | 左侧角色装备区域中的防具槽、武器主手槽和副手槽。 | 与右侧背包网格是两套独立布局；不能用“网格”代称。 |
| 主手 / 副手 | 武器区域的一对手持装备槽。 | 双手、远程和法系武器占用整组；单手武器可组成单手流派、双持或武器加盾牌流派。 |
| 技能槽 | 技能标签页中的主动或被动技能承载槽，以及其下方的符文小槽。 | 与装备槽、背包网格分开；不指按住右键打开的战斗法术界面。 |
| 法术界面 | 战斗中按住右键进入、松开右键退出的法术装配与选择界面。 | 仅当玩家手持魔导书、手持法杖，或手持单手剑且携带“奥法之剑”被动时允许进入。主体为 5 个法术槽位及各槽右侧的一列 3 个符文槽位，最右侧为符文列表。 |
| 法术槽位 | 法术界面主体中的 5 个大槽位；每个槽位展示其右侧 3 个符文槽位按固定配方解析出的法术。 | 不能与技能槽、装备槽混称；符文不足或组合无配方时显示为空法术。 |
| 符文槽位 | 每个法术槽位右侧纵向排列的 3 个小槽，用于装配参与该法术固定配方匹配的符文。 | 每个法术槽位独立保存 3 个位置；装配、移除或换位后立即重新解析对应法术。 |
| 符文列表 | 法术界面最右侧的可用符文清单，作为向符文槽位装配符文的来源。 | 不等同于物品页的背包网格；只展示当前可用于法术装配的符文。 |
| 固定法术配方 | 对 1 至 3 个有序符文标识进行精确匹配并得到唯一法术的静态配方。 | 配方不随机、不动态生成；相同符文但槽位顺序不同可对应不同配方，未登记组合不产生法术。每个已实现法术必须拥有唯一、无冲突的固定组合；配方表是法术界面解析的唯一来源。 |
| 法术图标 | 由法术 ID 与其明确意象元数据程序绘制的 128×128 像素卡面，用于法术槽位和法术图鉴。 | **意象优先**：每个法术必须先指定可被画出的核心意象，例如火球、冰矛、雷链、毒雾、石墙、治疗圣杯、召唤门等；图标中央必须直接表现该对象/动作，禁止只用抽象符文、同模板换色或文字首字母代替。**画布**：32×32 逻辑像素→128×128 最近邻 RGBA8，alpha 仅 0/1；切角深色卡面、元素/流派框体、场景化背景层、中央意象主体、硬边前景粒子/轨迹。**独立性**：所有法术完整 `Image.get_data()` 必须两两不同；相同元素法术也必须通过主体轮廓、运动方向、施法媒介与命中形态区分。**禁止**：抗锯齿、渐变、软发光、模糊、字体直绘、无语义噪点和外部 PNG 主体。标准接口与图鉴路径由实现文件规定，验收必须覆盖全部登记法术均有意象、配方和图标。 |
| 法术运行时 | 将 `SpellRecipeData` 已解析法术转化为可执行施法计划并在战斗中结算的唯一运行时边界。 | **单一入口**：玩家/UI/网络不得各自重写伤害、冷却和效果；必须先验证固定配方、法力、冷却、施法资格、目标与朝向，再产生结构化执行结果。服务端联机时必须重新按玩家身份和槽位解析，不信任客户端传入法术 ID、伤害或效果。**类别**：projectile、area、barrier、heal、movement、buff、summon 共享请求/结果协议，但各类别由独立执行器完成。**视觉分层**：运行时只发布施放/飞行/命中/区域视觉事件，不把粒子节点当权威伤害源；FX 缺失不得阻断结算。 |
| 像素法术视觉特效 | 法术施放、弹道、命中与持续区域的客户端视觉表现。 | 必须使用硬边像素块、短线、阶梯轮廓、体素碎片和离散轨迹；颜色与形状来自法术 `imagery`。禁止渐变、软光晕、模糊、平滑圆粒子和连续半透明烟雾。只有火焰、雷电、法术弹、符文爆发、传送门核心等明确能量现象允许 emission；Light3D 必须预算化，普通碎片/烟尘/受光表面不得自发光。FX 必须有生命周期、池化/上限和无渲染器安全路径。 |
| 奥法之剑 | 允许玩家在手持单手剑时使用法术界面的被动能力。 | 它只提供施法资格，不把任意其他武器视为法杖或魔导书。 |
| 悬浮窗 | 统一的装备/物品详情浮层，代码对象为 `EquipmentDetailPopup`。 | 物品页和战斗内指向物品时共用；不使用右侧固定详情栏替代。 |
| 交互提示悬浮窗 | 准心指向当前可执行交互的世界物体时显示的按键/动作提示，代码对象为 `InteractHint` 或 `PickupHint`。 | 与装备/物品详情“悬浮窗”分开；仅有碰撞体或 `interact()` 方法但当前没有实际交互效果的物体不得显示。准心离开、目标失效或交互条件不满足时，必须在同一物理帧发出空提示并立即隐藏。 |
| 地牢场景物体 | 只允许由 `scenes/props/dungeon/` 目录下的场景作为地牢生成链路的来源；包含地牢装饰、地牢容器和地牢专用碰撞/视觉配置。 | 地牢白名单、规划器、批处理装饰和调试捕获均只能引用该目录；不能把酒馆场景物体路径当作地牢装饰来源。 |
| 悬崖地形 | 以单个地牢房间为出现单位的连续可坠落下陷区（坑洞/深坑），至少由 4 个四方向相邻格组成；悬崖格是坑内危险区，不是高台、平台或普通临边。 | 悬崖格必须全部属于同一个房间，不能占用门前过渡、关键点或危险锚点；坑洞周围必须保留安全绕行路径，不能切断房间与地牢连通性。悬崖边缘/临边是独立的边界标记，不计入悬崖格；只允许通过地牢规划器与 `DungeonSceneBuilder` 生成。 |
| 酒馆场景物体 | 只用于酒馆手工场景或酒馆交互的家具、陈设和容器。 | 酒馆场景物体不能通过地牢运行时白名单、随机装饰池或房间装饰规划进入地牢；即使外观相同，也必须有独立的地牢场景资源。 |
| 整理 | 右侧背包网格的视觉整理操作：从左上开始填充，并按武器、护甲、材料、符文的类别顺序排列。 | 只重建当前显示顺序，不改变底层库存数据；与装备槽无关。 |
| 全部 / 装备 | 右侧物品页顶部的筛选按钮。 | 过滤背包网格内容；“整理”按钮位于筛选栏最右侧。 |
| 淡暗金色正方形色块 | 右侧背包网格中每个单元格的统一实心方块；物品图标、文字和品质线可以叠加在各自单元格内。 | 左右外边距必须分别与列间隙完全一致，上下外边距必须分别与行间隙完全一致；每个方块严格等宽等高，按同一左上基准上下左右对齐，间距一致；不允许方块重叠或侵占相邻单元格。方块之间的统一网格线留白和品质线允许保留；文字不得与选中框重叠；不能用于左侧装备槽。 |
| 属性图标 | 属性栏使用的像素风格图标。 | 统一按当前项目图标规格与对齐规则制作，不能用随意缩放或不对称的临时图形。 |
| 生命 / 蓝量 / 护盾计量仪表条 | 战斗 HUD 左下角的四种资源仪表：生命和蓝量常驻；魔法护盾、物理护盾仅在数值大于 0 时出现。 | **画布与结构**：每条固定 320×40；4px 为最小视觉单位；外壳必须是 8px 切角的深色八边形仪表底板，包含 4px 外描边、双层金属框、左侧 38px 类型铭牌、右侧资源槽与端部铆钉。**填充**：按 4px 整块取整，顶部高光 4px、主体色、底部暗边 4px，内部使用低对比度 8×4 像素纹理；每 28px 设置 2px 深色分段刻度。**类型**：生命=赤红+像素心脏；蓝量=青蓝+阶梯水晶；魔法护盾=奥术蓝+六角盾印；物理护盾=暖冷银+塔盾束带。**禁止**：平滑渐变、圆角、模糊、软发光、抗锯齿和亚像素线。数值与淡入淡出继续由 `CombatHUD`、`PixelBar.set_values()`、`ShieldBar.set_values()/deactivate()` 驱动，绘制层不得改动结算。验收预览为 `reports/ui_preview/resource_bars_1280x720.png`。 |
| 符文图标 | 由 `data/rune_glyphs.gd` 按符文 ID 程序绘制的 128×128 像素风格完整卡面。 | **画布**：32×32 逻辑像素，4×最近邻放大到 128×128 RGBA8；alpha 只能为 0/1。**卡面**：`2..29` 切角轮廓，暗色石板纹理背景，深描边+金属双层边框、四角铆钉、家族色框饰和中央单符文主体。**主体**：2px 逻辑主笔画、硬边高光节点；元素/战斗/神秘/黑暗/神圣五大家族必须有不同框饰与骨架。**禁止**：抗锯齿、渐变、平滑曲线、软发光、字体直绘、运行时外部 PNG 作为主体。所有已登记符文必须逐像素确定性生成且不能完全相同；标准接口 `RuneGlyphs.get_texture(rune_id, 128)`，验收图鉴 `reports/ui_preview/rune_codex_128px.png`。完整说明见 `19-符文系统（构筑深度）.md` §3.2。 |
| 符文之语图标 | 由 `data/rune_word_glyphs.gd` 为每个符文之语 ID 单独程序绘制的 128×128 华丽像素圣匣徽记。 | **不可复用规则**：每个 `word_id` 必须拥有独立完整纹理；不得只按主题复用同一背景、边框或中央徽记后仅换色/换宝石。至少四层必须同时受 `word_id` 稳定种子影响：内场连续刻线、边框刻度/缺口、中央签名字形、冠饰线型布局。完整 RGBA 像素数据在全部登记之语之间必须两两不同。**叠加方块边界（用户裁定）**：除底部按配方顺序排列的 2–3 颗符文色宝石方块外，背景、边框、顶部冠饰、侧边和中央徽记区域均禁止出现孤立或叠加的小方块/方形节点；独立差异必须改用连续折线、刻痕、缺口和轮廓变化表达。**固定结构**：32×32→128×128 最近邻；八角圣匣、深描边、三层稀有度金属框、主题冠饰、独立中央复合签名、底部配方宝石。**主题**：动力/守御/元素/奥秘/黑暗/神圣只定义视觉语言，不得成为共享成品模板。**禁止**：平滑圆环、渐变、半透明、模糊、软发光、字体直绘。标准接口 `RuneWordGlyphs.get_texture(word_id, 128)`，验收图鉴 `reports/ui_preview/rune_word_codex_128px.png`；测试必须比较完整 `Image.get_data()`，不能只抽样少数像素。完整说明见文档 §3.3。 |
| 像素风格滤镜 | `PixelView` 提供的低分辨率渲染后再以最近邻放大的全屏画面滤镜。 | 与材质的像素着色 / Toon 光照是两个独立功能；关闭滤镜不得修改 `pixel_shader_enabled`。当前默认关闭。 |
| 区域地图 / 地图选区 | 远征前用于选择目的地的像素风格地图；“地图选区”是地图上与 `ZoneManager` 区域一一对应的可点击标记。 | 取代纵向文字区域列表。当前必须呈现幽暗地牢、寂静之森、深邃洞窟、荒芜墓园、熔岩火山、古代遗迹六区；名称、描述、难度与颜色继续读取 `ZoneManager`，点击选区只确定候选目的地，确认“开始探险”后才写入并进入地牢。 |
| 楼层 | 当前远征在所选区域内的地下层级，从 `L1` 开始；进入向下楼梯后递增为 `L2`、`L3`，并在地牢重载时保留。开始新远征、撤离或失败后的下一次远征重新从 `L1` 开始。 | 楼层是远征运行时状态，不改变区域选择和区域材料配置；界面常驻显示 `L<n>`。 |
| 向下楼梯 | 地牢特殊房间内的像素/体素风楼梯场景物体，包含可见台阶和玩家触发区域。玩家进入触发区域后进入下一楼层，不触发撤离结算。 | 由 `DungeonSceneBuilder` 生成，`DungeonRuntime` 接通信号；楼梯触发必须使用 `PhysicsSetup.LAYER_TRIGGER` / `PhysicsSetup.LAYER_PLAYER` 碰撞契约并具备一次性保护。 |
| 楼层到达提示 | 到达地牢（包括 `L1`）时在屏幕中央显示“区域名称 + 楼层标识”的大字提示，例如“幽暗地牢 · L1”。提示淡入、保持 1 秒、再淡出；切换楼层或地牢重载不会残留上一层提示。 | 由 `ExpeditionHUD` 驱动，不参与地牢结算；常驻楼层标识与中央到达提示是两个独立控件。 |
| 熟练度 | 武器熟练度页面中的武器类别熟练度。 | 仅武器拥有熟练度；不区分单双手；剑覆盖所有剑类和剑流派。 |
| 角色经验 | 玩家通过击杀怪物获得的成长进度；达到当前等级所需经验后触发升级，超出的经验继续保留并可连续触发多次升级。 | 只奖励给完成有效击杀归属的玩家；不是武器熟练度、酒馆声望或远征结算资源。 |
| 升级选择 | 每次角色升级产生的一次待处理成长选择，玩家必须在“六维中的一个属性 +1”与“获得一次符文机会”之间二选一，两种奖励严格互斥。 | 多次连续升级会形成选择队列；前一次选择完成后再处理下一次，不能重复结算同一级。升级窗口以悬浮面板显示在战斗 HUD 之上，保留 HUD 与战斗场景可见。 |
| 符文机会 | 升级选择的一种结果：从三个互不重复的候选符文中选择一个并加入玩家符文库存。 | 进入符文候选即放弃本次升级的属性提升，不能返回属性分支或刷新候选；候选来自当前可获取符文池，不等同于法术界面的符文槽位，也不直接改变固定法术配方。 |
| 弩身轴 / Z 轴 | 弩模型沿弩身长度方向的建模轴，源自 Blender 的 `Z` 轴；第一人称相机不滚转，整体姿态只沿弩身中轴做 `45°` 局部滚转，灰色弩臂必须平行于画面横轴，弩身/导轨继续指向视角中心。 | 不等同于弩臂横向轴；用于弩的整体挂点、导轨指向和第一人称姿态校验。 |
| 桌面白色泛光 / 倒影 | 当前酒馆视觉问题中，桌面或吧台台面上出现的白色亮斑/亮条；与蜡烛本体发光、火焰粒子和其他物体材质发白分开定位。 | 先判断是否来自台面材质的镜面项，再判断点光源造成的漫反射过曝；不能将其直接归因于蜡烛倒影。 |
| 人形怪物 | 具有可持握武器的手部/武器挂点、攻击模式为 `weapon` 的怪物。当前已验收名单包括哥布林、兽人掠夺者、骷髅兵、巨魔、牛头怪、卓尔剑士和地精类人形怪物。 | 追击到武器射程后使用装备武器攻击；不能退化为身体攻击。 |
| 非人形怪物 | 不以持握武器为攻击形态、攻击模式为 `body` 的怪物。当前包括史莱姆、巨型蜘蛛、巨龙和岩石魔像。 | 追击到自身身体攻击范围后使用身体攻击；不能依赖 `WeaponData` 或武器挂点判定攻击。 |
| 出身 | 新游戏开始时选择的玩家背景身份，替代传统职业系统。仅提供初始属性偏移（主属性 +3 / 副属性 +1）、一件初始武器和势力关系微调，不锁定任何后续成长路径。 | 共 4 个：退役佣兵 / 林间猎人 / 半吊子术士 / 矮人学徒。详见 `docs/36-出身系统与涌现式Build.md`。 |
| 熟练度阶梯 | 武器熟练度达到 20/40/60/80/100 时解锁的渐进奖励（伤害/攻速/暴击/大师被动/终极加成）。 | 与技能领悟门槛（T1/T2/T3）独立共存；熟练度硬上限 100。 |
| 撤离引导 | 玩家在撤离点主动交互后进入的短暂等待状态；普通负重需 1.5 秒，负重达到容量 70% 后需 2 秒。 | 踏入撤离区域不会自动撤离；引导期间不能移动但可以战斗，再次交互、离开撤离区域或受到伤害会取消。完成引导后才结算本次远征。 |

## 更新规则

1. 每次开始会话，在进行 UI 或领域代码修改前，必须完整读取本表。
2. 用户对术语作出澄清、纠正或重新命名时，应立即在本表中更新，并以最新定义继续工作。
3. 若旧截图、旧实现或变量名与本表冲突，以本表和用户最新解释为准；必要时同步修正代码注释与测试，避免歧义回归。
4. 新增会影响 UI 布局、交互或数据流的术语时，应先补充本表，再继续实现相关改动。
