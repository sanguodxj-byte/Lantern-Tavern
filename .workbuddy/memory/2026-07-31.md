## 小地图改为同步探索进度（与大地图一致）
- 需求：小地图此前只绘制玩家周围 `world_radius`(25m) 局部窗口，远处已探索区域(探索进度)
  不显示，与大地图(展示完整已探索地牢)不一致。要求小地图也同步探索进度。
- 根因：大地图与小地图**共享同一份**探索状态(`minimap._explored_cells`)，差异只在渲染范围——
  大地图遍历全网格只画已探索格；小地图只遍历 `world_radius` 窗口内的格。
- 修复(`scenes/ui/minimap.gd`, 提交 b019741)：新增 `_update_view()` 以"已探索区域包围盒"为
  基准算 `_view_center`/`_view_scale`/`_view_cell_r`；已探索区域大时自动缩小以展示完整进度，
  否则退化为玩家中心局部视图(旧行为)。`_draw_grid_map`/`_draw_collision_map`/`_draw_enemies`/
  玩家箭头均改用该视图变换。保留"随视角旋转、玩家箭头朝上、敌人仅视野内"风格。
- 测试新增 `tests/gdunit/minimap_test.gd`(2 例全过)；`large_map_test` 26/26 通过(共享 API 未破)。
- 注意：`large_map_test` 之外 `combat_hud_test` 有 1 例 `test_shield_bar_physical_color_is_gray`
  失败——经用旧 minimap.gd 复跑确认是**预存失败**(与 combat_hud.gd 工作区旧改动有关)，
  与本改动无关，勿误判为回归。

## 符文图标改为程序化绘制（弃用生图位图）
- 用户要求：符文图标用程序绘制、不使用生图，方便后续扩展。
- 背景问题：50 个符文原靠 `assets/textures/icons/runes/*.png` 生图，其中 43/50 为不透明
  RGB 主题色瓦片(四角实心填充)，违反 AGENTS 强制的"绿底→去绿底→透明"工作流；
  且 `load(".../*.png")` 触发 "Loaded resource as image file will not work on export" 警告。
- 方案(提交 150e20c)：新增 `data/rune_glyphs.gd`，以归一化(0..1)矢量图元
  (line/disc/ring/poly/polyline/arc) 在运行时 CPU 光栅化为 `ImageTexture`
  (无需渲染器，headless/导出均可用)。确定性按 `rune_id.hash()` 播种，每符文图形
  稳定且各异(如尼文风格：中轴+支线)；颜色复用 `rune_data.RUNE_COLORS`。
  `_overrides` 字典支持为某符文手工登记专属图元覆盖自动生成。
- 接线：`equipment_detail_popup.gd:icon_for_rune` 改调 `RuneGlyphs.get_texture`，
  不再依赖 PNG；`rune_icon_path` 保留返回旧 PNG 路径仅兼容 detail 字典。
  4 个消费点(tavern_equipment_panel / chest_loot_panel / 两个 capture 工具)
  经 `icon_for_rune` 取 Texture2D，无需改。
- 测试：新增 `tests/gdunit/rune_glyphs_test.gd`(6 例全过)；
  `equipment_detail_popup_test` 两个依赖 PNG 的用例改为验证程序化纹理；
  `chest_loot_panel_test` 84 例无回归。
- 遗留待清理(未删，需用户确认)：`assets/textures/icons/runes/*.png`(50) 与
  `futhark/`(24 死资产，全代码库无引用) 现已冗余；`docs/19-符文系统` 仍写 7 符文/
  Futhark，应更新到 50 梵语符文并注明图标已程序化。
