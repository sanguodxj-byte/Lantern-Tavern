## 宝箱界面：武器拖入左装备栏无法装备（UI 连通性 bug 修复）

### 根因
`scenes/ui/chest_loot_panel.gd` 的 `_setup_drop_zone(equip_grid, "equipment")` 把 drop zone
脚本挂在 `EquipGrid` (GridContainer) 上，但网格里每个槽位都是 Button 子节点，完全盖住父容器。
Godot 的 drop 事件只派发给光标下**最顶层** Control，因此把武器拖到槽位上时 drop 落在 Button 上
被默认拒绝 → 无法装备。

### 修复（已提交 ce7844c98，仅 2 文件：chest_loot_panel.gd + chest_loot_panel_test.gd）
1. `_refresh_equipment_grid():` 空槽保持 `disabled=false`（禁用按钮在部分引擎版本下不收 drop 事件），
   并让**每个装备槽 Button 自身**也 `_setup_drop_zone(btn, "equipment")` 成为拖放目标。
2. `can_drop_to_zone` / `drop_to_zone` 的 "equipment" 分支：新增允许来自宝箱栏的拖放，
   新增 `_equip_chest_item_to_player(loot_idx)` 取出即装备、绕开背包中间态、持久化到 GameState。
3. `_on_list_gui_input` 背包装备**右键**直接装备到玩家（新增测试 `test_panel_backpack_right_click_equips_equipment`）。

### 测试
- `chest_loot_panel_test.gd` 全部 82 例通过（exit 0）。
- `test_panel_cannot_drop_to_equipment_from_chest` 改名为 `..._can_...` 并断言 `is_true()`。
- `test_panel_drop_to_chest_returns_from_backpack` 改为按 `\nfunc ` 函数边界截取整个 `drop_to_zone`
  函数体，避免固定 600 字符窗口因函数变长被截断误判（之前的 exit 100 失败源）。

## 三网格区域拖曳连通性审查（同会话）

三个拖放区：equipment(EquipGrid+每槽Button) / backpack(BackpackList, ItemList) / chest(ChestList, ItemList)。
拖放源：chest_list→source="chest"；backpack_list→source="backpack"；装备槽Button→source="equipment"。
ItemList 的条目是绘制而非独立节点，无子节点遮挡，故 backpack/chest 两个 drop zone 本身连通正常；
遮挡 bug 仅存在于 equip_grid（已由上述修复解决：每个槽 Button 自挂 drop zone + 空槽 disabled=false）。

连通性矩阵（can_drop_to_zone 全 9 组合已用临时 GDUnit 测试验证，exit 0）：
| 源\目标   | equipment | backpack | chest |
|----------|-----------|----------|-------|
| equipment| 拒绝(自身) | ✓ 卸下    | ✗ 拒绝 |
| backpack | ✓ 装备     | 拒绝(自身)| ✓ 放回 |
| chest    | ✓ 装备     | ✓ 取物   | 拒绝(自身)|

结论：6 条交叉路径中 5 条连通，唯独 **equipment→chest 不连通**（can_drop "chest" 分支仅放行 source=="backpack"）。
这是设计取舍而非 bug：宝箱是单向 loot 源，已允许 backpack→chest 放回，但装备栏不能直接拖入宝箱。
待用户确认是否需补齐 equipment→chest（若补，需在 drop_to_zone "chest" 新增 equipment 分支处理卸下入箱+持久化）。

### 关键坑：Python 改写 .gd 误转 CRLF（已记入项目 MEMORY.md）
用 `open(path,"w",encoding="utf-8")` 改 Godot 脚本会把 LF→CRLF（Windows 默认换行），
导致 Godot `script.source_code` 长度多出 ~行数 个字符（本例 38790→39878），
使基于 `source.substr(find("func _close()"),500)` 的测试因 `close_loot_panel` 被推到窗口外而误判失败。
修复：用 `open(path,"w",encoding="utf-8",newline="\n")` 转回 LF。**改 Godot 文件一律加 newline 参数。**
